## 항목 2. 어떻게 했나

**Q. 외부 → IGW → Subnet → EC2 흐름을 설명하면?**
내 PC가 퍼블릭 IP로 요청하면 IGW가 주소를 프라이빗 IP로 바꿔 VPC 안으로 넣고, 서브넷의 SG가 80을 허용해 EC2의 Nginx까지 갑니다. 응답은 SG가 기억한 연결이라 통과하고, Route Table의 `0.0.0.0/0 → IGW`를 따라 나갑니다.

**Q. VPC `10.0.0.0/16`, 서브넷 `10.0.1.0/24`는 무슨 뜻인가?**
VPC가 쓸 사설 IP 범위입니다. 앞 16비트 `10.0`을 고정해 `10.0.0.0`부터 `10.0.255.255`까지 약 6.5만 개를 쓰고, 서브넷 `10.0.1.0/24`는 그 안에서 256개를 잘라 쓴 구역입니다. ([그림](images/cidr.svg))

**Q. SG 규칙은 어떤 기준으로 최소화했나?**
서비스와 관리에 꼭 필요한 것만 열었습니다. 80은 서비스용이라 전체, 22는 관리용이라 내 IP `/32`만 열고, 443·DB 포트·전체 포트는 쓰지 않으니 열지 않았습니다.

**Q. 외부 검증은 무엇을 골랐고 무엇을 구성했나?**
B(`/health`)를 골랐습니다. 고정 응답이라 성공 여부가 분명하고 응답 코드까지 터미널로 증빙되기 때문입니다. Nginx에 `location = /health`를 추가했고, SG 80 허용과 퍼블릭 IP 자동 할당을 함께 구성했습니다.

**Q. 리소스는 어떻게 추적하고 정리했나?**
모든 리소스에 태그 `Project=b3-1`과 이름 `b3-1-*`을 달고, 만들 때마다 체크리스트에 ID를 적었습니다. 정리는 그 목록대로 안쪽부터 지우고 EC2 Global View로 다른 리전까지 확인했습니다.

## 항목 3. 왜 그렇게 했나

**Q. `0.0.0.0/0 → IGW` 경로가 왜 필요한가?**
기본 경로는 VPC 안(`local`)뿐이라, 요청이 들어와도 응답이 VPC 밖으로 나갈 길이 없습니다. 이 경로가 있어야 응답이 IGW로 나가고, 그래서 퍼블릭 서브넷이 됩니다.

**Q. SG와 IAM은 무엇이 다르고, 최소 권한은 왜 필요한가?**
SG는 서버로 오는 패킷을, IAM은 AWS를 조작하는 API 호출을 통제합니다. 최소 권한은 키가 유출되거나 실수해도 피해를 그 권한 범위 안으로 묶어 둡니다.

**Q. SSH(22)나 DB 포트를 `0.0.0.0/0`으로 열면 안 되는 이유와 대안은?**
포트 스캔 봇이 항상 돌고 있어 바로 무차별 대입 공격을 받습니다. SSH는 내 IP `/32`와 키 인증(또는 Session Manager)으로, DB는 Private Subnet에 두고 앱 서버 SG에서 오는 것만 허용합니다.

**Q. 트러블슈팅에서 왜 가설 → 검증 순서를 지켰나?**
한 번에 여러 개를 바꾸면 원인을 알 수 없고, "다 열기" 같은 위험한 해결로 가기 쉽기 때문입니다. `curl`의 timeout/refused 차이, `access.log` 기록 유무, 콘솔 화면을 근거로 썼습니다. ([troubleshooting.md](troubleshooting.md))

## 항목 4. 상황이 바뀌면

**Q. 외부 접속이 안 되면 어떤 순서로 보나?**
바깥에서 안으로 봅니다. Route Table(`0.0.0.0/0 → IGW`, 서브넷 연결) → SG(80) → 퍼블릭 IP(있는지, 바뀌었는지, `https://`로 접속하지 않았는지) → 서버(`systemctl status nginx`, `curl localhost`, 로그) 순서입니다.

**Q. IAM 권한이 부족해 실패하면?**
관리자 권한을 주지 않습니다. 에러 메시지에 나온 거부된 액션(예: `ec2:CreateRoute`) 하나만 정책에 추가하고 다시 시도합니다.

**Q. 인스턴스를 2대로 늘려야 한다면?**
지금은 EC2 1대, AZ 1개라 단일 장애점이고, IP 하나로 접속해서 트래픽을 나눌 수 없습니다. 다른 AZ에 서브넷을 하나 더 만들고 ALB를 앞에 둬서 `/health`로 상태를 확인하며 나눠 보내고, EC2의 SG는 ALB에서 오는 80만 허용합니다.

**Q. Billing에 예상 못한 비용이 찍히면?**
Cost Explorer에서 서비스별, 리전별로 나눠 봅니다. 실행 중인 EC2(타입, Unlimited 크레딧) → 연결 안 된 Elastic IP·퍼블릭 IPv4 → 남은 EBS·스냅샷 → NAT Gateway·ALB → 다른 리전 리소스(Global View) 순서로 의심하고 정리합니다.
