# B3-1 핵심 개념 정리

이 과제에 나오는 용어를 **특징 / 왜 필요한가 / 하는 일** 기준으로 정리했다.
각 개념 옆의 `[항목 N]`은 관련 평가 항목이다.

---

## 0. 한 줄로 보는 전체 흐름

```
요청: 내 PC → (퍼블릭 IP) → IGW(퍼블릭→프라이빗 IP 변환) → VPC 내부 경로(local) → Public Subnet
      → Security Group(80 허용, 연결 기억) → EC2(Nginx)
응답: EC2 → Security Group(기억된 연결이라 통과) → Route Table(0.0.0.0/0 → IGW)
      → IGW(프라이빗→퍼블릭 IP 변환) → 내 PC
```

Route Table의 `0.0.0.0/0 → IGW`는 **응답이 VPC 밖으로 나갈 때** 쓰인다. 그림은 [guide.md의 외부 접속 흐름](guide.md#외부에서-접속할-때의-흐름-요청과-응답-왕복)을 본다.

요청이 서버까지 가려면 **길(라우팅) + 주소(퍼블릭 IP) + 문(보안 그룹) + 받는 사람(웹 서버 프로세스)** 네 가지가 모두 있어야 한다.

## 1. 위치와 주소

### Region / AZ (가용 영역) `[항목 4]`
- **특징**: Region은 지리적 지역(서울 = `ap-northeast-2`), AZ는 그 안의 독립된 데이터센터 묶음(`ap-northeast-2a` 등)이다.
- **왜 필요한가**: 리소스가 어디에 생기는지 정해야 지연 시간, 비용, 장애 범위를 관리할 수 있다.
- **하는 일**: 리소스는 리전 단위로 분리되고, 서브넷은 하나의 AZ에 묶인다. 다른 리전에 실수로 만든 리소스는 해당 리전 화면에서만 보이므로 과금 추적 시 주의해야 한다.

### CIDR `[항목 1, 3]`
- **특징**: IP 범위를 `주소/숫자`로 표기한다. 숫자가 클수록 범위가 좁다.
  - `/16` = 약 65,536개, `/24` = 256개, `/32` = 딱 1개, `0.0.0.0/0` = 인터넷 전체
- **왜 필요한가**: 네트워크 크기를 정하고, "누구를 허용할지"를 범위로 표현하기 위해서다.
- **하는 일**: VPC(`10.0.0.0/16`), 서브넷(`10.0.1.0/24`), SG 규칙(`내IP/32`)의 범위를 지정한다.

### Private IP / Public IP `[항목 1, 4]`
- **특징**: Private IP는 VPC 안에서만 쓰는 주소, Public IP는 인터넷에서 접근 가능한 주소다. 자동 할당된 Public IP는 인스턴스를 Stop/Start하면 바뀐다.
- **왜 필요한가**: 외부 사용자는 Private IP로 접근할 수 없다. 인터넷에 서비스하려면 Public IP가 있어야 한다.
- **하는 일**: IGW가 Public IP ↔ Private IP를 1:1로 변환해 외부 요청을 EC2로 전달한다.

### Elastic IP (EIP) `[항목 1, 4]`
- **특징**: 고정된 Public IP. 직접 할당하고 직접 해제(Release)해야 한다.
- **왜 필요한가**: 재시작해도 주소가 바뀌면 안 되는 서비스에 쓴다.
- **하는 일**: 인스턴스에 고정 주소를 붙인다. **인스턴스에 연결되지 않은 EIP는 과금 대상**이다.
- **이번 과제**: 할당하지 않음. 자동 Public IP로 충분하다.

## 2. 네트워크

### VPC (Virtual Private Cloud) `[항목 1, 2]`
- **특징**: AWS 안에 만드는 나만의 격리된 가상 네트워크. 다른 계정·다른 VPC와 기본적으로 분리된다.
- **왜 필요한가**: 서버를 아무 네트워크에나 두면 경계가 없다. 내가 IP 범위와 출입 경로를 통제할 공간이 필요하다.
- **하는 일**: 서브넷, 라우팅, 게이트웨이, 보안 그룹이 모두 이 안에서 동작한다.

### Subnet (Public Subnet) `[항목 1, 2, 3]`
- **특징**: VPC를 더 작게 나눈 구역으로, 하나의 AZ에 속한다. **"퍼블릭"이라는 속성이 따로 있는 게 아니라, 라우트 테이블에 `0.0.0.0/0 → IGW` 경로가 있으면 퍼블릭 서브넷이다.**
- **왜 필요한가**: 외부에 노출할 것(웹 서버)과 숨길 것(DB)을 구역으로 나누기 위해서다.
- **하는 일**: EC2가 실제로 배치되는 위치. "퍼블릭 IPv4 자동 할당" 설정이 켜져 있어야 EC2에 Public IP가 붙는다.

### Route Table `[항목 1, 3, 4]`
- **특징**: "목적지가 어디면 어디로 보낸다"는 규칙표. 서브넷과 연결(Association)되어야 적용된다.
  - `10.0.0.0/16 → local`: VPC 내부 통신 (기본으로 존재)
  - `0.0.0.0/0 → IGW`: 그 외 모든 목적지는 인터넷으로
- **왜 필요한가**: `local` 경로만 있으면 VPC 밖으로 나가는 패킷의 목적지가 없다. 외부 요청에 대한 **응답도 나갈 수 없다.**
- **하는 일**: 서브넷에서 나가는 트래픽의 경로를 정한다.

### Internet Gateway (IGW) `[항목 1, 2, 3]`
- **특징**: VPC와 인터넷을 잇는 관문. VPC당 1개를 Attach한다.
- **왜 필요한가**: IGW가 없으면 Public IP가 있어도 VPC가 인터넷과 연결되지 않는다.
- **하는 일**: 인바운드·아웃바운드 인터넷 트래픽을 통과시키고 Public ↔ Private IP를 변환한다.
- **정리 시**: VPC에서 Detach한 후 삭제해야 한다.

### NACL (Network ACL) — 설정하지 않음 `[항목 4]`
- **특징**: 서브넷 단위 방화벽. stateless(응답도 규칙이 필요), 허용과 거부 모두 가능하다. 기본값은 전체 허용이다.
- **이번 과제**: 기본값 유지. 접속 장애 점검 시 "기본값 그대로인지" 확인만 한다.

## 3. 보안

### Port (포트) `[항목 2, 3]`
- **특징**: 한 서버 안에서 어떤 프로그램에게 갈지 구분하는 번호. IP가 건물 주소라면 포트는 호수다.

| 포트 | 용도 | 이번 과제 |
|---|---|---|
| 22 | SSH (서버 관리 접속) | 내 IP `/32`만 허용 |
| 80 | HTTP (웹) | `0.0.0.0/0` 허용 |
| 443 | HTTPS | 미허용 (HTTPS 미사용) |
| 3306 / 5432 | MySQL / PostgreSQL | 미허용 (DB 없음) |

- **왜 필요한가**: 열린 포트 = 외부에서 두드릴 수 있는 문이다. 필요한 문만 열어야 공격 표면이 줄어든다.

### Security Group (SG) `[항목 1, 2, 3, 4]`
- **특징**:
  - 인스턴스 단위 가상 방화벽
  - **허용 규칙만** 있음 (거부 규칙 없음, 명시하지 않은 것은 모두 차단)
  - **stateful**: 들어온 요청에 대한 응답은 아웃바운드 규칙과 무관하게 자동 허용
- **왜 필요한가**: 서버가 인터넷에 노출되는 순간 포트 스캔 봇이 접근한다. 필요한 포트만 열어야 한다.
- **하는 일**: 어떤 출발지(IP 범위)에서 어떤 포트로 오는 트래픽을 받을지 결정한다.
- **SSH를 `0.0.0.0/0`으로 열면 안 되는 이유**: 전 세계에서 무차별 대입 공격 대상이 된다. 대안은 내 IP `/32` 제한, 키 인증만 허용, Session Manager 사용이다.

### IAM (Identity and Access Management) `[항목 1, 3, 4]`
- **특징**:
  - **루트 계정**: 모든 권한, 제한 불가 → 일상 작업에 쓰지 않음
  - **IAM 사용자**: 사람이 로그인하는 계정
  - **정책(Policy)**: "어떤 액션을 어떤 리소스에 허용/거부"를 적은 JSON 문서
  - **역할(Role)**: 서비스나 사용자가 잠시 빌려 쓰는 권한
- **왜 필요한가**: 계정이 유출되거나 실수했을 때 피해 범위를 권한 범위로 제한하기 위해서다.
- **하는 일**: 누가 AWS API(리소스 생성·삭제·조회)를 호출할 수 있는지 통제한다.

### SG vs IAM 차이 `[항목 3]`

| 구분 | Security Group | IAM |
|---|---|---|
| 통제 대상 | 네트워크 트래픽 (패킷) | AWS API 호출 (리소스 조작) |
| 질문 | 누가 **서버에 접속**할 수 있나? | 누가 **AWS를 조작**할 수 있나? |
| 예시 | 80 포트를 누구에게 열까 | EC2를 누가 만들고 지울 수 있나 |

### 최소 권한 원칙 (Least Privilege) `[항목 3, 4]`
- **특징**: 작업에 꼭 필요한 권한만 주고, 그 외는 주지 않는다.
- **왜 필요한가**: 권한이 넓을수록 유출·실수 시 피해가 커진다.
- **이번 과제 적용**: EC2 관련 액션만, 서울 리전에서만 허용. S3/RDS/IAM 권한과 AdministratorAccess는 주지 않는다.
- **권한이 부족할 때**: 에러 메시지에서 거부된 액션 이름을 확인 → 그 액션만 추가한다. 관리자 권한으로 한 번에 해결하지 않는다.

### Key Pair / SSH `[항목 1]`
- **특징**: 공개키는 EC2에, 개인키(`.pem`)는 내가 보관한다. 개인키는 재발급되지 않는다.
- **왜 필요한가**: 비밀번호 대신 키로 인증해 무차별 대입 공격을 막는다.
- **하는 일**: `ssh -i key.pem ubuntu@<퍼블릭IP>`로 서버에 접속한다. `chmod 400 key.pem`이 필요하고, 레포에는 절대 올리지 않는다.

## 4. 서버

### EC2 / 인스턴스 타입 `[항목 1, 4]`
- **특징**: AWS의 가상 서버. 인스턴스 타입은 CPU·메모리 사양을 뜻한다. t3.micro는 평소 낮은 성능을 쓰다 필요할 때 크레딧으로 순간 성능을 올리는 버스트형이다.
- **왜 필요한가**: 웹 서버 프로그램을 실행할 컴퓨터가 필요하다.
- **주의**: t3 계열은 계정 기본값이 Unlimited 모드라서, 크레딧을 다 쓰면 추가 과금될 수 있다. 인스턴스 생성 시 고급 설정에서 **Standard**로 바꾼다. (t2는 기본값이 Standard)

### AMI `[항목 1]`
- **특징**: EC2를 만들 때 쓰는 OS 이미지 (예: Ubuntu 24.04 LTS).
- **하는 일**: 인스턴스의 초기 디스크 내용을 결정한다.

### EBS `[항목 1, 4]`
- **특징**: EC2에 붙는 네트워크 디스크. 인스턴스를 Stop해도 데이터와 **과금이 유지**된다.
- **정리 시**: Terminate하면 **인스턴스를 만들 때 붙어 있던 볼륨만** 기본으로 함께 삭제된다. 나중에 따로 붙인 볼륨은 남아서 계속 과금되므로, 볼륨 목록이 비어 있는지 직접 확인한다.

### Nginx `[항목 1, 2, 4]`
- **특징**: 웹 서버 프로그램. 80번 포트에서 HTTP 요청을 기다린다.
- **하는 일**: 요청이 오면 페이지 또는 `/health` 응답을 돌려준다.
- **확인 명령**:
  - `systemctl status nginx`: 실행 중인지
  - `ss -tlnp | grep :80`: 80 포트를 열고 기다리는지
  - `/var/log/nginx/access.log`: 요청이 서버까지 도착했는지
  - `/var/log/nginx/error.log`: 설정·처리 오류

### Health Check (`/health`) `[항목 1, 2]`
- **특징**: 서비스가 살아있는지 확인하는 전용 주소. 항상 고정된 짧은 응답(`200 OK`, `OK`)을 준다.
- **왜 필요한가**: 사람·모니터링 도구·로드밸런서가 서버 상태를 기계적으로 판단하기 위해서다.
- **이번 과제**: 검증 방식 B로 사용. Nginx 설정에 `location = /health`를 추가한다.

## 5. 점검 도구

### curl `[항목 1, 3, 4]`
- `curl -i URL`: 응답 코드와 헤더 확인 (`HTTP/1.1 200 OK`)
- `curl -v URL`: 연결 과정까지 자세히 확인

| 결과 | 의미 | 의심할 곳 |
|---|---|---|
| **timeout** (응답 없음) | 패킷이 서버에 도달하지 못함 | 라우팅, SG, Public IP |
| **connection refused** | 서버엔 도달했지만 받을 프로그램이 없음 | Nginx 프로세스, 포트 |
| **200 OK** | 정상 | — |

### 외부 접속 장애 점검 순서 `[항목 4]`
1. Route Table: `0.0.0.0/0 → IGW` 경로와 서브넷 연결
2. Security Group: 80 인바운드 허용
3. Public IP: 존재하는지, Stop/Start로 바뀌지 않았는지, `https://`로 접속하고 있지 않은지
4. 서버 내부: Nginx 실행 여부 → 80 포트 대기 여부 → `curl localhost` → 로그

바깥 계층부터 안쪽으로 좁혀간다.

### CloudTrail 이벤트 기록 `[항목 3, 4]`
- **특징**: 계정을 만들 때부터 자동으로 켜져 있다. **최근 90일**의 관리 작업(API 호출) 기록을 리전별로 보여주고, 조회는 무료다.
- **왜 필요한가**: "누가, 언제, 무엇을 만들고 지웠는지"의 근거가 된다. 권한 오류(AccessDenied)도 여기에 남는다.
- **하는 일**:
  - IAM 권한 부족 시: 거부된 API 이름을 찾아 그 액션만 정책에 추가한다.
  - 정리 증빙: `TerminateInstances`, `DeleteVpc` 같은 이벤트로 삭제 사실을 보여줄 수 있다.
  - 스크린샷을 놓쳤을 때 대체 근거로 쓸 수 있다.
- **주의**: 이벤트는 작업이 일어난 리전에만 보인다. 조회하려면 `cloudtrail:LookupEvents` 권한이 필요한데, 이번 과제의 IAM 사용자에는 **주지 않았다**(과제가 EC2/VPC/SG 범위로 권한을 제한하라고 요구). 개념으로만 알아 둔다.

## 6. 비용과 정리

### 프리 티어 / 과금 요인 `[항목 1, 4]`
- **특징**: 신규 계정에 일정 사용량을 무료로 제공한다. 범위를 넘거나 대상이 아닌 리소스는 과금된다.
- **대표 과금 요인**: 실행 중인 EC2(대상 외 타입·Unlimited 크레딧), 미연결 EIP, Public IPv4, 미사용 EBS·스냅샷, NAT Gateway, ALB, 다른 리전에 남은 리소스
- **예상치 못한 과금 시**: Cost Explorer에서 서비스별·리전별로 확인하고, EC2 Global View로 전 리전 리소스를 찾는다.

### Tag (태그) `[항목 2]`
- **특징**: 리소스에 붙이는 `키=값` 라벨 (`Project=b3-1`).
- **왜 필요한가**: 실습 리소스를 한 번에 찾아 정리하고, 비용을 추적하기 위해서다.

### 정리 순서 `[항목 1, 2]`
EC2 Terminate → (EBS 삭제 확인) → 키페어 → SG → Subnet / Route Table → IGW Detach 후 삭제 → VPC

의존 관계가 있는 것(안에 들어있는 것)부터 지워야 바깥 리소스가 삭제된다.

- Terminate한 EC2는 **약 1시간 동안만** 목록에 Terminated 상태로 보이다가 사라진다. 정리 증빙 스크린샷은 Terminate 직후 바로 찍는다.
- Terminate 후에는 인스턴스 요금은 멈추지만, 남은 볼륨이나 해제하지 않은 EIP는 계속 과금된다.

## 7. 확장 시 개념 (설정하지 않음, 설명용) `[항목 4]`

### ALB (Application Load Balancer)
- **특징**: 들어오는 요청을 여러 EC2에 나눠 보낸다. **2개 이상 AZ의 서브넷이 필요**하다.
- **왜 필요한가**: 현재 구조는 EC2 1대가 단일 장애점이고, 사용자는 IP 하나로 접속하므로 트래픽을 나눌 수 없다.
- **추가 시 구조**: ALB(퍼블릭) → EC2 2대(각 AZ). EC2의 SG는 ALB의 SG에서 오는 트래픽만 허용한다.

### NAT Gateway
- **특징**: Private Subnet의 서버가 인터넷으로 **나가는 것만** 가능하게 한다. 시간당 과금이 크다.
- **이번 과제**: 사용하지 않음. 과금 의심 1순위 리소스로만 기억한다.

### Private Subnet
- **특징**: `0.0.0.0/0 → IGW` 경로가 없는 서브넷. 외부에서 직접 접근할 수 없다.
- **용도**: DB처럼 외부에 노출하면 안 되는 서버를 둔다.
