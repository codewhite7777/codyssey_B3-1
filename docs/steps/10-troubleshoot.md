# 10단계. 트러블슈팅 재현하기

[← 단계 목록](../guide.md) · [이전: 9단계](./09-verify.md) · [다음: 11단계 →](./11-cleanup.md)

> **한 줄 요약**: SG에서 80 규칙을 일부러 빼서 고장을 만들고, 근거를 따라 원인을 찾은 뒤 복구한다.

## 1. 무엇을, 왜

| 항목 | 내용 |
|---|---|
| 무엇을 | 장애 재현 → 근거 수집 → 원인 확정 → 한 가지만 조치 → 재확인 |
| 왜 | 제출물인 트러블슈팅 보고서에 **증상 → 가설 → 검증 → 조치 → 결과 → 재발 방지**를 실제 근거와 함께 남기기 위해 |
| 어디서 | 🖱️ 콘솔, `$` 내 PC, `ubuntu@...$` EC2 안 |

## 2. 할 일

| 순서 | 어디서 | 할 일 | 보이는 것 |
|---|---|---|---|
| 1 | 🖱️ | SG `b3-1-sg-web`에서 HTTP 80 규칙 삭제 | 인바운드에 22만 남음 |
| 2 | `$` | `curl -v --max-time 10 http://<퍼블릭IP>/health` | 응답 없이 **timeout** |
| 3 | `ubuntu@...$` | `curl -i http://localhost/health` | 200 OK → Nginx는 정상 |
| 4 | `ubuntu@...$` | `sudo tail -n 5 /var/log/nginx/access.log` | 내 PC의 요청 기록이 **없음** → 요청이 서버에 오지 않음 |
| 5 | 🖱️ | Route Table, SG 차례로 확인 | 경로는 정상, SG에 80 없음 → 원인 확정 |
| 6 | 🖱️ | 80 규칙 하나만 다시 추가 | — |
| 7 | `$` | 2번 명령 다시 실행 | 200 OK, `access.log`에 내 IP 기록 |
